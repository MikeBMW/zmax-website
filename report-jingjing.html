三、核心问题（What/Why/How，按严重性降序）

问题 1：长轨迹插拔训练"越训越差"（BC 多阶段退化）

What：视觉 BC 端到端直接学完整插拔，仿真成绩 0/8；多阶段拼接仍退化。
Why：底层症结——插拔是"长时程+强时序依赖"任务，单网络端到端难以同时建模"该抓的时刻"（接触判定）与"怎么动"（连续动作）；接触反馈信息在长轨迹中被淹没。
How：架构决策——拆成左右脑：左脑专注连续动作生成（39D→4D），右脑世界模型预测接触时刻（contact 概率），中间 8 状态机做阶段调制（接近→对位→下降→抓取→抬起→转移→插入→完成）。
结果：抓起 8/8、插入 7/8，超官方专家 7/8；MLP 蒸馏 6/10、速度自适应实验 4-6 全部对照。

问题 2：仿真转移卡顿，控制参数调不动

What：转移阶段速度自适应实验（0.6/0.35/0.15 分级）抓起 6-7 但插入 4-6 未改善。
Why：根因排查到仿真物理碰撞（销钉与孔边缘/台面几何干涉）——无接触反馈的控制参数调不动，是环境问题不是策略问题。
How：三组对照实验（纯增强 vs 速度自适应×3 重复 + 降波动）定位根因 → 止损转向真机力控夹爪 + 插入前 YOLO 视觉对准。
结果：不再浪费算力调仿真参数，明确下一步技术路线（真机力控+视觉）。

问题 3：触觉信息怎么用（接触反馈的架构位置）

What：contact 判定结果往哪送——直觉是"喂给模型"，但喂给左脑会造成输入分布漂移。
Why：接触信号是离散时序事件，与连续动作生成通道不匹配。
How：实测决定——contact 只作状态机转移条件（该抓了吗），不喂左脑；状态机反过来调制左脑输出（接近×0.3+偏置×2、抓取×0.1+夹持 0.6、转移速度自适应、插入力控）。
结果：模块边界清晰，左右脑职责单一，可独立训练/替换（0.71M 总参数、0.19ms）。

问题 4：工程化落地多轮踩坑（环境/链路/分发）

What/Why/How：conda 环境损坏→容器训练（zmax-std:1.0，torch2.11+cu128 可复现）；GUI 卡死→子线程+QTimer 防重入改造；飞书 PDF 推送失败→glob 模式与实际文件名不匹配（五模型对比 vs Model Zoo）修复两处；视频/文档打不开→WSL 无播放器+UNC 路径被拒→C 盘复制+explorer 打开链路。
结果：▶运行=一键训练、帮助文档可打开、飞书群推送成功、场景仿真上线。

五、经验总结（理念与思路）

  • 可控模型 · 可控架构 · 可控指标（三控原则）：每个需求都有模型归属、架构落点、可测量指标——工程交付的质量锚点（写进协议第 1.2 节）。
  • 决策分层优于端到端：接触判定（世界模型）与动作生成（左脑）分离 + 状态机调制，比单网络端到端更稳、更可解释、更可调。
  • 根因优先于调参：转移卡顿 3 组实验定位物理碰撞根因，止损转向真机路线——不浪费算力在错误环境上。
  • 数据闭环：采集→训练→评估→部署→采集，每环节可追溯（曲线 JSON / 评估报告 / checkpoint 全留痕）。
  • 效率优先：追求最简路径（容器训练 3000 步 1.5 分钟验证、配置现场 sed 生成 runtime），快速出结果。

规划（1 年）
